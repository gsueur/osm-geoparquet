Query it

With DuckDB, a file is a table. Counting the buildings of Midtown Manhattan reads a few row groups of a 335 MB file:

INSTALL httpfs; LOAD httpfs; INSTALL spatial; LOAD spatial;

SELECT count(*) AS buildings
FROM read_parquet('https://parquetry.geomermaids.com/osm/latest/country=US/state=US-NY/buildings.parquet')
WHERE bbox.xmin <= -73.98 AND bbox.xmax >= -73.99
  AND bbox.ymin <= 40.76  AND bbox.ymax >= 40.75;

More in the Querying Parquetry cookbook: spatial joins, nearest features, whole-continent queries through our anonymous S3 endpoint, GeoPandas and QGIS. New to DuckDB? Start with the Reading cookbook.

URLs and snapshots

https://parquetry.geomermaids.com/osm/<YYYY-MM-DD | latest>/country=<CC>/state=<ISO 3166-2>/<theme>.parquet

# e.g. every building in New York State, today
https://parquetry.geomermaids.com/osm/latest/country=US/state=US-NY/buildings.parquet

Dated snapshots never change, so a pinned date gives the same answer next year. We keep every day for 14 days, then the first of each month for a year, then December 31 of each year for good. snapshots.json lists what is available. Need a date kept? Ask us.

Inside each file

  • Native Parquet GEOMETRY type, GeoParquet 2.0, with geospatial statistics per row group.
  • A bbox column, so engines that don't understand GEOMETRY (Spark, Trino, polars) can still skip row groups on a bounding box.
  • Rows in Hilbert order, so a bounding-box query reads a few neighbouring row groups instead of the whole file.
  • Bloom filters on the typed columns and on tags: a lookup such as name = 'Central Park' skips every row group that cannot hold it.

Built with osmium-tool and DuckDB, and validated every night before it is published; the files pass gpio check. The pipeline is open source (MIT): github.com/gsueur/osm-geoparquet.

STAC catalog

A Portolan (STAC) catalog describes each theme: columns, extents, row counts, and a glob that reads every region at once. osm/catalog/catalog.json follows latest/; osm/catalog/<date>/catalog.json pins a kept snapshot. It is listed in the Portolan registry and opens in the STAC browser. GAUL has its own: gaul/catalog/catalog.json.

How it compares

Geofabrik is our upstream: their daily regional extracts, in PBF, Shapefile and GeoPackage, are what we start from. Overture Maps publishes worldwide GeoParquet every month, merging OSM with other sources under its own schema. We keep OSM's own tags, publish daily, and split by state so one URL is one manageable file.

OSM infrastructure preview

The content of Open Infrastructure Map, as GeoParquet: power lines, circuits, substations, plants and generators; telecom cables, masts and data centres; pipelines, wells and platforms; water works. Voltages are parsed to kV per circuit, outputs to MW, and plants and substations are assembled from their OSM relations. 27 layers, each with the full OSM tags.

https://parquetry.geomermaids.com/osm-infrastructure/latest/country=<CC>/state=<name>/<layer>.parquet

# e.g. the power lines of Bayern, Germany
https://parquetry.geomermaids.com/osm-infrastructure/latest/country=DE/state=bayern/power_line.parquet

# every power line on the planet, in one file
https://parquetry.geomermaids.com/osm-infrastructure/latest/world/power_line.parquet

States are the GAUL first-level units, named in the path; offshore features sit under state=_offshore. The whole planet, built from Geofabrik's continental extracts, one file per layer and state, and each layer again as one world file whose row groups a bbox filter skips (a glob over thousands of small files spends minutes on their footers). Only the latest build is kept, and columns may still change.
